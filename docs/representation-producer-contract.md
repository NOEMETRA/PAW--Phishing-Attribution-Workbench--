# Representation producer and owned client preparation (P3)

`representation_producer.py` supplies Root-only execution and publication
functions for already installed representation grants. It has no CLI, issuer,
readiness installer or ordinary-operator command. Existing fixed recipes do
not call it in this increment. A reviewed immutable release, actual owned
normal/fault matrices and scoped I08 acceptance remain required before use.
The active Root snapshot is unchanged by adding these libraries.

Execution accepts the canonical full request and an already installed exact
policy. It reobserves the maintained context and loads the existing grant;
the separately reviewed adapter performs durable one-use consumption before
guest creation. Control paths are fixed beneath `/var/lib/paw-s14/control`,
selected only by the validated request ID. Existing Python/BrowserVM classes
retain their images, no-NIC lifecycle, identities and resource budgets. The
HTML media remains private to Root/QEMU and is copied without interpretation.
No caller command, URL, interpreter or arbitrary host path is delegated.

Each private audit contains policy/readiness, maintenance, image provenance
and a complete copy of the active immutable selected PAW/lab runtime. The
source is read from protected operator state and verified by the existing
physical snapshot verifier, then reconciled with the authority's canonical
source-inventory hash. Every nested destination uses protected descriptor-
relative creation and bounded exclusive file writes. A caller cannot select
another snapshot or supply local JSON as release authority.

The producer checks actual host restoration, no remaining domains, immutable
base/canary bytes and unchanged maintained context after stopping the VM.
Private reports are bounded and replaced atomically. A failed independent
verification changes the stored initial PASS to FAIL; failed execution or
unknown stop never reaches the successful verifier. This intermediate private
audit is distinct from a trusted client export. Protected outer operator state
continues to use its existing scalar contract; these VM reports retain finite
duration floats separately and are not embedded in that state.

Publication independently rechecks the serialized audit in analysis mode,
the current protected policy/readiness, active context, original request,
installed grant and durable consumed ledger. It does not turn an owned-validation
policy into production readiness. The image proof must equal the protected
current file. HTML uses its existing browser certificate; Python uses the
existing base provenance record and a fresh local check of the fixed Ubuntu
manifest signature, without network/package operations. The independent
Python custody verifier binds this record's image/hash, native byte count,
signed-manifest claim and expected signer metadata. The offline copy is custody
evidence; the controlled Root producer supplies the local trust boundary.

A successful publication creates a fresh private request-ID directory beneath
`/var/lib/paw-s14-representation-exports`, containing only the original request,
versioned receipt and bounded ordinal opaque artifacts. Hashes bind the actual
request/selection/source, grant/policy/readiness/consumption/context, job,
runtime report, source inventory, image proof and stopped VM. The existing
protected-reader publisher exposes the directory only after writing completes.
An existing destination refuses; a grant cannot be consumed again. No output
is rendered or expanded on the host. The established client imports this
receipt into a separately sealed sidecar while preserving the original case.

`representation_owned_inputs.py` generates six finite harmless fixtures from
a bounded nonce: parser-selected Python, malformed Base64 Python/HTML,
quoted-printable Python/HTML and original HTML. It never executes their source
on the host. Its client refuses Root and uses actual PAW inspection/selection
CLI operations, externally known stop and seal verification. It checks exact
original/selected hashes, explicit unique node selection, original inventory
preservation and private request files. Source and installed modes verify the
actual package location. The output authorizes no execution.

Future unattended integration must invoke that client only after dropping UID
and capabilities, with fixed arguments from the immutable recipe. Root must
read its output as untrusted bounded data and independently match the fixed
owned source/request approvals; a user-writable venv must never execute as
Root. The ordinary operator still accepts only its existing finite recipe
names, and its no-guest runtime recipe keeps that meaning. No real-source
approval is installed or inferred from these tests.

The new tests substitute Root locations/ownership and physical hardware while
performing real temporary snapshot/inventory verification, exclusive authority
installation/issue/consumption, serialized custody checks, receipt creation and
client sidecar sealing. They check tampered snapshots, pending symlinks, bounded
atomic results, failed verification, protocol/stop failures, missing readiness,
replay/existing export refusal and unchanged original cases. These are inert
boundary tests, not actual Root/KVM/I08 acceptance. Actual source and installed
CLI preparation of all six new cases is also checked without grant or guest.

The supported lab inventory becomes126 files within the existing128 cap,
reserving two modules for the finite P4 profiles. Test code remains outside
that privileged inventory. P3 remains open for the controlled nonroot client
invocation, owned Root recipes/fault verifier, actual no-NIC matrices and scoped
I08 plus source/installed VM round trips; P4/P5 remain open.
