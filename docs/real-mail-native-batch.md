# One native batch for three selected mail URLs

This increment adapts the existing no-NIC browser and existing DNS/HTTP/TLS
transport to one explicitly authenticated three-source operation. It adds no
HTTP parser, TLS stack, route, bridge, NAT, Docker configuration, permanent
polkit action, operator recipe or generic passwordless command. Source/scoring,
original case files and their seals remain unchanged. The native operation is
not enabled by preparing a request, passing CI or merging this code.

## Authority and sequence

The existing operator independently promotes the reviewed immutable release.
Its current owned kernel/browser acceptance must pass on that exact release.
A native authenticated PID1 master then admits a digest-bound data bundle for
exactly three distinct EML SHA256 identities and their explicitly selected URLs,
parent case references and selected BLAKE3 snapshots. The one compiled owned
parent is separate. No real mail, recipient or tracking path belongs in GitHub.
The fixed bundle also pins the current browser/image/maintenance context,
Wi-Fi binding, system CA and exact Ubuntu Python3.14 BLAKE3 binary files. Those
three hash dependency files are installed only under protected Root state;
workspace/site packages are never imported as HostRoot.

The source/hash selection authorizes the selected live navigation and bounded
resources; live site response hashes cannot be known beforehand. It does not
permit attachments, submitted forms, credentials, downloads or arbitrary host
commands. The native prompt must present the actual three source hashes,
target hosts, tracking disclosure, limits and immutable release/bundle digest.
No password is retained. This is one authentication for a finite batch, not a
promise that future code changes or new batches need no native authorization.

The master holds the deployment lock and its authority requires the same live
PID1 controller/PID identity, unexpired protected scope and unrevoked operator.
Each serial child consumes a private job marker, with fixed PID1 cleanup hooks.
Before real work, five actual private namespace packet scenarios check closed
rules, DNS-only tuples, established response expiry, coordinator SIGKILL and
one deleted guard. The SIGKILL gate requires the protected established-stream
marker and independent PID1 signal9/exit metadata, not any failing exit code.
Five additional compiled inert contract checks cover private DNS answers,
rebinding, redirect overflow, truncated protocol and uncertain byte charges;
they explicitly do not claim actual network faults. A fresh complete owned
browser capture then uses this same adapter and checks its nonce/JS marker.

The master waits at most180s for installed PAW to import that owned result,
verify it and export its exact ZIP. An ordinary readonly descriptor carries the
actual sidecar and ZIP bytes, not a passed:true assertion. Root reconstructs the
expected protected capture, checks every BLAKE3 inventory/root and ZIP member
without extraction, then consumes one batch marker before three serial real
attempts. No real connection is allowed if any owned gate is missing or fails.
Master/child death ends authority; fixed stop hooks revoke and stop remaining
roles. Cleanup works after expiry/revocation and only stops protected job IDs.

## Confinement and unchanged ceilings

Chrome remains sandboxed/nonroot inside the existing no-NIC VM with no host
shares. The old controller already denies downloads and permissions, intercepts
requests before navigation and closes unsupported child targets. Public capture
changes only the selected seed and completion oracle; it preserves bounded
DOM/PNG transfers and proves renderer/cgroup termination before publication.

Only a dedicated nonroot transport opens IPv4 sockets, in a readonly private
RootDirectory with no host home/data mounts, no capabilities, NNP/seccomp and
one-use typed private stdin/stdout. For real work it explicitly shares the host
network namespace; it is not a networked guest and not a host CLI lookup.
Two independent timed nft tables select its reserved UID on output and its exact
systemd socket cgroup on input. Public/special address filtering, physical
interface/source binding, cgroup BPF allowlists and expiring numeric tuples all
apply. Incoming established traffic still requires a live tuple. Guard cleanup
retains default drop until the worker is independently stopped; removing a guard
cannot race a still-live BindsTo-dependent transport. No fallback if socket
cgroupv2/BPF support or current host context is unavailable.

Owned packet/browser gates use the same profiles and rules on private loopback
aliases, with no default route or physical egress. The namespace difference from
real operation remains explicit. Alias setup uses a pinned namespace descriptor,
with PID1/pidfd checks before mutation; later roles must match its protected
namespace inode, so PID reuse cannot redirect configuration to the host. A
positive DNS tuple followed by deny-all BPF also checks that denied packets do
not reach the owned fixture. Original five-recipe operator controls remain
unchanged. Root allocations are master64MiB/8tasks/15%, coordinator192/24/35%,
guard64/8/10%, transport128/16/25%, owned fixture64/8/15%: total512MiB/64/100%.
Real work has no fixture. QEMU remains1536MiB/64tasks/50%, guest1GiB, browser15s,
guard8s, transport10s, external stop12s. No budget expands for this operation.

The user-selected policy is at most8 URL hostnames,32 HTTP attempts and4MiB
response bytes across the three emails, five redirects per navigation. A stricter
fixed allocation admits at most10 attempts and1398101 response bytes per email
(total30 attempts/4194303 bytes); unused allocation is not transferred. The three
initial hostnames reserve slots before discovery. Protected accounting carries
between children. Unknown transport outcomes consume the whole pending byte
reservation; no unobserved bytes are refunded. Kernel relative lease time is
recomputed after BPF changes and retains the existing2s commit reserve.

## Custody and limits of meaning

Reader exports bind the batch/slot, exact request/source/parent, immutable
release, VM/image/Chrome/context, actual stop and every opaque byte artifact.
Only known stopped writers and restored host state permit publication. Partial
DOM survives a later PNG transfer error; consumed streams never restart. Failed
or truncated coverage remains failed/partial, never a malicious verdict.
Response bodies/DNS packets are separate finite opaque files; network metadata
remains at most1MiB and DOM/PNG at most256KiB each. Empty HTTP bodies are valid.

`paw lab-mail-browser prepare` is offline data preparation with no grant/launch.
`import --batch ... --slot owned|0|1|2` independently checks the original stopped
case and protected result and publishes a separate sealed sidecar. Existing
`paw verify`/`paw export` apply. `prepare-ack` packages the actual owned sidecar/ZIP;
`submit-ack` uses only the already-running protected AF_UNIX rendezvous. Neither
command starts a Root process or guest. Status exports are advisory, not authority.

Observations cover the main page and filtered broker exchanges. They are not a
complete HAR, browser TLS fingerprint, reputation result, email authentication,
actor attribution or calibrated classification. TLS verification belongs to the
broker. HTTP/1 decoding, DNS record support, identity encoding and all existing
refusals stay finite; unavailable sites and unsupported formats remain explicit.
The paired report must distinguish added observations from changed conclusions.
