## Data contract and CLI

`paw lab-owned-mail-browser prepare --case CASE --output NEW` verifies the actual
BLAKE3 seal and stopped PAW writers as the ordinary user, then binds the exact
fixed source, selected URL, parent reference and bounded original parent pieces.
It creates `PREPARED_NOT_ACTIVE` data with `execution_authority:none` and a900s
admission lease. Arbitrary original bytes/URLs, authority claims, changed limits,
parent substitution, changed selected bytes and invalid clocks refuse. It starts
no Root helper, browser, socket or DNS operation.

`paw lab-owned-mail-browser import --case CASE --request REQUEST --output NEW`
requires the matching protected local Root export, known whole-tree stop and
host restoration, complete artifact hashes/inventory and an unchanged, valid
parent case. Successful capture additionally requires all three declared
artifacts and the existing complete renderer sandbox witness. Failed, timed out,
cancelled or refused terminal captures may retain partial artifacts honestly.
The sidecar is sealed before its stable result directory is published. Reusing
an output container refuses; copying existing evidence to another container is
not an execution grant or a replay of the VM job.

Directory creation, file writes, the finite-file BLAKE3 seal and publication use
pinned no-follow directory descriptors. Renaming an output ancestor cannot
redirect these writes into the original case. The named destination must still
identify the pinned directory before success is reported. Linux atomic
`RENAME_NOREPLACE` refuses an existing stable result. Interrupted or detached
outputs remain unpublished outside the parent; this does not promise to prevent
the filesystem owner independently modifying their own files afterwards. The
seal uses the existing case index/root format and is checked by the ordinary
case verifier in the regression tests.
